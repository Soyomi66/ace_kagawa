# 文字起こしの文末で話し終わりを判定する（案 A、日本語、オフライン）

実施日: 2026-11-02 / 対象: `ace_kagawa`

目的: 応答を速くするため、VAD の 0.6 秒の沈黙待ちを「VAD 0.2 秒で止まるたびに、そこまでの文字起こしの文末を見て判定する」方式に置き換えられるかを確かめる。Smart Turn v3（声の抑揚で判定）は日本語で使えなかった（`smart-turn-v3-ja-2026-11-02.md`）ので、その代わりの案。本番の Tokkio・controller・ASR サービスには触れていない。

## 結論

**来訪者の質問では使える。判定は約 0.4 秒速くなり、発話を途中で切る割合は今とほぼ同じ。** 長い読み上げ（FLEURS）では切る割合が 16% → 26% に増える。

| 音声 | 方式 | 途中で切った発話 | 言い終わりから判定まで（ASR 込み） p50 / 平均 | 規則ですぐ判定 |
| --- | --- | ---: | ---: | ---: |
| 来訪者の質問 160 本（合成） | 今（VAD 0.6 秒＋Qwen3-ASR） | 11/160（6.9%） | 0.69 / 0.68 秒 | — |
| | **案 A（Qwen3-ASR＋文末規則）** | 14/160（8.8%） | **0.28 / 0.29 秒** | 89% |
| | 案 A（Haas＋文末規則） | 13/160（8.1%） | 0.22 / 0.25 秒 | 88% |
| | 参考: Smart Turn CPU 版（ASR 時間を含まない） | 58/160（36.2%） | 0.19 秒 | 62% |
| FLEURS 650 本（人の読み上げ） | 今（VAD 0.6 秒＋Qwen3-ASR） | 105/650（16.2%） | 0.77 / 0.77 秒 | — |
| | 案 A（Qwen3-ASR＋文末規則） | 166/650（25.5%） | 0.36 / 0.36 秒 | 74% |
| | 案 A（Haas＋文末規則） | 168/650（25.8%） | 0.25 / 0.25 秒 | 74% |
| | 参考: Smart Turn CPU 版 | 373/650（57.4%） | 0.19 秒 | 42% |

- 案 A は VAD 0.2 秒、規則が「まだ続く」と判定したときの待ち上限 0.8 秒、規則は `lex`（2 節）。
- **今の Qwen3-ASR のままで使える。** Haas への切り替えとは独立に決められる。Haas は認識が速い分（区切りごとの p50 43 ms 対 115 ms）、さらに約 0.06 秒縮む。
- 来訪者の 14 対 11 件の差は 160 本中 3 本で、誤差の範囲。増えた分は「はい｜お願いします」「いいえ｜大丈夫です」のように、短い返事のあとに 0.4〜0.6 秒置いて続ける発話（3.1 節）。
- **話し終わりから最初の声までは、約 1.34 秒 → 約 0.9 秒の見込み。** 今の内訳は VAD 0.6 秒＋STT 0.07 秒＋LLM の最初の句と TTS の最初の音声 0.61 秒（2026-10-17 の実マイク、`speech-cpp-asr-2026-10-17.md` 7.5 節）。案 A ではこのうち VAD＋STT が約 0.3 秒になり、残る最大の部分は LLM＋TTS の 0.61 秒になる。
- 規則で判定できず待ち上限まで待つ発話は、来訪者で 4/160（Haas 7/160）。これらは今より 0.2 秒遅い（0.8 秒）。待ち上限を 0.6 秒にすると、遅くはならないが、来訪者で切る割合が 10.0% になる。

## 1. 方法

### 1.1 動かし方（Smart Turn の評価と同じ VAD・切り出し）

| 部分 | 再現した動き |
| --- | --- |
| VAD | Silero VAD、確信度 0.7、開始 0.2 秒、停止 0.2 秒（`scripts/turn_eval.py` の結果を流用） |
| 文字起こし | VAD が止まるたびに、話し始めの 0.7 秒前からその時点までの音声を ASR に送る（それまでのターン全体を毎回書き起こし直す） |
| ASR | speech.cpp 0.10.1 の `speech serve`、Vulkan0（物理 GPU 1、描画と共有）、`--threads 4`。Qwen3-ASR-1.7B Q8_0 と Haas-ja-v1.0 Q8_0、どちらも `language=ja`、プロンプトなし |
| 判定 | 規則が「言い終わり」→ その時点で確定。「まだ続く」→ 話が再開すれば続け、沈黙が待ち上限に達したら確定 |
| 判定までの時間 | 規則で確定: max(0.2 秒, VAD 停止 − 発話の終わり)＋ASR 時間。待ち上限で確定: 上限の秒数 |
| 今の方式の時間 | VAD 0.6 秒の停止までの時間＋同じ測定の最後の区切りの ASR 時間 |

「途中で切った」は、最後の発話区間より前でターンが確定したもの。アバターが質問の前半だけで答え始める状況に当たる。

ASR 時間は今回の測定（GPU 1、連続で送信）の値で、実マイクでの値（0.07 秒）とは違う。今と案 A の両方に同じ測定を使ったので、差は比べられるが、秒数そのものは本番と一致しない。

### 1.2 規則（結果を見る前に固定）

規則は `scripts/textend_rules.py` に、結果を見る前に書いて固定した（SHA256 `b0190e2f…`、写しは `textend/textend_rules.frozen.py`）。

| 規則 | 「言い終わり」とする条件 |
| --- | --- |
| `punct` | ASR が付けた「。」「？」「！」で終わる |
| `lex` | 句読点は見ない。文末が「です・ます・ました・ください・か・ね・よ・た・る・い」などで終わるか、短い返事（「はい」「いいえ」「なるほど」など）。ただし「、」で終わるもの、助詞・接続助詞（「の・を・に・は・が・て・けど・ので」など）やフィラー（「えっと」「あの」）で終わるものは「まだ続く」 |
| `both` | `lex` と同じ「まだ続く」の条件。そうでなければ、句読点か `lex` のどちらかで「言い終わり」 |
| `strict` | **結果を見てから足した（独立した検証ではない）。** 短い返事、または句読点と `lex` の両方 |

**両方の ASR に `lex` を使う。** Qwen3-ASR はほぼすべての文字起こしを「。」で終えるので、`punct` は使えず（来訪者で 70.6% を途中で切る）、`both` は「まだ続くでなければ言い終わり」と同じになる（FLEURS で 40.9%）。Haas は `both` でも来訪者の値はほぼ同じ（8.1%、平均 0.24 秒、即判定 89%）、FLEURS では `lex` より悪い（27.7%）。

### 1.3 評価した音声

| セット | 中身 |
| --- | --- |
| 来訪者の質問 | 160 本、Irodori の合成音声（4 話者）、10/17 の ASR 評価と同じ。文中の 0.2 秒以上の間は 125 か所 |
| FLEURS ja_jp test | 650 本、人の読み上げ、平均 13 秒。Wikipedia の文で、1 本に 2 文以上のものが多い。文中の間は 818 か所 |
| 難所セット | Irodori の合成。言いかけ 15 文（「〜けど、」「えっと、」「〜の」）と短い返事 15 文（「はい。」「いいえ。」）× 4 話者 |
| 公式テスト日本語 | `pipecat-ai/smart-turn-data-v3.2-test` の日本語 834 本（Google Chirp 3 の合成）。発話全体を 1 回書き起こして判定 |

## 2. 詳細

### 2.1 規則・VAD 停止・待ち上限の比較（来訪者の質問）

| ASR | 規則 | VAD 停止 | 待ち上限 | 途中で切った | 判定まで p50 / p90 / 平均 | 規則ですぐ判定 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3-ASR | `lex` | 0.2 | 0.6 | 16/160（10.0%） | 0.28 / 0.31 / 0.29 | 88% |
| | **`lex`** | **0.2** | **0.8** | **14/160（8.8%）** | **0.28 / 0.31 / 0.29** | **89%** |
| | `lex` | 0.3 | 0.8 | 14/160（8.8%） | 0.38 / 0.41 / 0.39 | 89% |
| | `punct` | 0.2 | 0.8 | 113/160（70.6%） | 0.27 / 0.30 / 0.27 | 29% |
| Haas | `lex` | 0.2 | 0.6 | 16/160（10.0%） | 0.22 / 0.23 / 0.24 | 86% |
| | **`lex`** | **0.2** | **0.8** | **13/160（8.1%）** | **0.22 / 0.23 / 0.25** | **88%** |
| | `both` | 0.2 | 0.8 | 13/160（8.1%） | 0.22 / 0.22 / 0.24 | 89% |
| | `punct` | 0.2 | 0.8 | 7/160（4.4%） | 0.80 / 0.80 / 0.56 | 39% |

- VAD 停止を 0.3 秒にしても来訪者では切る割合は変わらず、0.1 秒遅くなるだけ。FLEURS では Haas 25.8% → 22.0%、Qwen3-ASR 25.5% → 21.5% に減る（判定は 0.35〜0.46 秒）。
- Haas の `punct` は切る割合が低いが、Haas は「。」を付けないことが多く、6 割が待ち上限まで待つので速くならない。
- 全組み合わせ（4 規則 × VAD 0.2〜0.4 秒 × 上限 0.6〜1.0 秒）は `textend/summary_all.md`。

### 2.2 FLEURS（人の読み上げ）

| ASR | 今（VAD 0.6 秒） | 案 A（`lex`、0.2 / 0.8） |
| --- | ---: | ---: |
| Qwen3-ASR | 105/650（16.2%）、0.77 秒 | 166/650（25.5%）、0.36 秒 |
| Haas | 105/650（16.2%）、0.66 秒 | 168/650（25.8%）、0.25 秒 |

Haas の 168 件の内訳（参照テキストの文の切れ目から ±2 文字以内なら「文の切れ目」）:

| 切れた場所 | 間 < 0.6 秒（今なら切らない） | 間 ≥ 0.6 秒（今も切る） |
| --- | ---: | ---: |
| 規則が文の切れ目で「言い終わり」（2 文目の前で答え始める） | 59 | 22 |
| 規則が文の途中で「言い終わり」 | 28 | 7 |
| 待ち上限（0.8 秒）で確定 | — | 52 |

- **今より増える 87 件のうち 59 件は、読み上げの 1 文目と 2 文目の間（0.3〜0.5 秒）。** 来訪者が「〜したいです。いつですか？」のように 2 文で話すと、1 文目で答え始める。来訪者の質問ではこの形が少ないため差が小さかった。
- 文の途中の 35 件（28＋7）のうち 28 件は、語尾が「る・た・い・う」（「ください」を含む）の箇所。「予定していた｜」「〜に対する｜」「〜からなる｜」のように後ろの名詞を修飾するものが目立つ（種類別には数えていない）。FLEURS は「だ・である」調なので文末も同じ語尾になり、単語の一覧では区別できない（3.2 節）。
- Qwen3-ASR も同じ傾向（文の切れ目 57＋21、文の途中 27＋9、待ち上限 52）。

### 2.3 難所セット

| 判定 | Qwen3-ASR `lex` | Haas `lex` | 参考: Smart Turn CPU 版 |
| --- | ---: | ---: | ---: |
| 言いかけを「言い終わり」と誤判定（アバターが割り込む） | 4/59（7%） | 6/59（10%） | 14/59（24%） |
| 短い返事を 0.2 秒で「言い終わり」と判定 | 55/60 | 54/60 | 37/60 |

- 誤判定した言いかけ: Qwen3-ASR の 4 件はすべて「そうですね。」（考えながらの「そうですね、」）。Haas はそれに加えて「それで、い」「先生の研究で、た」（言いかけの語の頭を書き起こしたもの）。
- 判定できなかった短い返事: 4 件は「こんにちは」（規則の不具合、3.2 節）。ほかは Haas の「ハイ、お願いシマス」（カタカナ）、「学費はいくらですか?ん?」など。

### 2.4 公式テスト日本語 834 本（参考）

| 規則 | Qwen3-ASR | Haas |
| --- | ---: | ---: |
| `lex` | 90.0%（未完を完了 38/414、完了を未完 45/420） | 89.2%（42/414、48/420） |
| `both` | 91.1% | 91.2% |

Smart Turn は同じデータで 96.16%。ただしこのデータは合成音声で、末尾の無音が短く（中央値 25 ms）、文中の間がない。実際の発話（FLEURS・来訪者）で比べると、文中の間を「言い終わり」としない分、案 A のほうがはるかに切らない（結論の表）。

### 2.5 聞こえる切断（取り消しと結合を入れた場合）

「途中で切った」のうち、アバターが声を出す前に話者が話を再開したものは、応答を取り消して前の発話とつなげれば、来訪者には気づかれない。ターン確定から最初の声までの時間を T として、話者がそれより後に再開した（＝聞こえる）切断の数:

| ASR | セット | 今（VAD 0.6 秒）: 切断 → T 0.3 / 0.5 / 0.8 秒で聞こえる | 案 A: 切断 → T 0.3 / 0.5 / 0.8 秒で聞こえる |
| --- | --- | --- | --- |
| Qwen3-ASR | 来訪者 | 11 → 6 / 4 / 2 | 14 → 10 / 5 / 5 |
| | FLEURS | 105 → 37 / 21 / 10 | 166 → 52 / 27 / 11 |
| Haas | 来訪者 | 11 → 6 / 4 / 2 | 13 → 9 / 5 / 4 |
| | FLEURS | 105 → 52 / 28 / 15 | 168 → 61 / 29 / 12 |

- 本番の T は、文字起こしから最初の声まで 0.61 秒（10-17 の実マイク）から、話の再開を VAD が検出する 0.2 秒を引いた約 0.4 秒。T 0.3 と 0.5 の間に当たる。
- **T 0.3〜0.5 秒では、来訪者で聞こえる切断は今の 6〜4 件に対し案 A は 10〜5 件**（Qwen3-ASR）。FLEURS は 37〜21 件に対し 52〜27 件。T が 0.5 秒に近いほど差は縮む。どちらも取り消しと結合を実装した場合の数字で、実装しなければ上の「切断」の数そのものになる。
- 同じ仕組みは今の方式でも効く（左列）。

## 3. 見つかった問題

### 3.1 来訪者の質問で切った発話（Qwen3-ASR `lex`、14 件）

| 種類 | 件数 | 例（｜が切れた場所、括弧は間） |
| --- | ---: | --- |
| 短い返事のあとに続ける | 11 | 「はい｜お願いします」（0.54〜1.86 秒）、「いいえ｜大丈夫です」（0.45〜1.92 秒）、「すみません｜もう一度…」（0.51〜1.06 秒） |
| 連体修飾の「た」 | 2 | 「AIを使った｜非破壊検査の研究はありますか」（0.42 秒、0.61 秒） |
| 待ち上限で確定 | 1 | 「八王子みなみ野駅から｜バスは出ていますか」（1.06 秒） |

うち 5 件は間が 0.6 秒未満で、今の VAD 0.6 秒なら切らない。

### 3.2 規則の不具合（固定した規則のまま、数字は直していない）

| 不具合 | 影響 | 直し方 |
| --- | --- | --- |
| 「こんにちは」が「は」で終わるので、短い返事より先に「まだ続く」と判定される | 難所 4/60 が待ち上限まで待つ（切断にはならない） | 短い返事の完全一致を先に調べる |
| 「そうですね」は返事にも、考えながらのつなぎにもなる | 難所の誤判定 4/59 はすべてこれ | 一覧から外すと、返事の「そうですね。」が 0.8 秒待つ。どちらを取るかは実マイクで決める |
| Haas はカタカナで書くことがある（「ハイ」「シマス」） | 難所 1/60 | カタカナをひらがなに変えてから判定 |
| 普通形の「る・た・い・う」が名詞を修飾する箇所（「AIを使った｜非破壊検査の…」「予定していた｜」「〜に対する｜」） | 来訪者 2 件。FLEURS の文中誤り（Haas）35 件のうち、語尾が「る・た・い・う」のものが 28 件 | **単語の一覧では直せない。** 形態素解析で次に名詞が来やすいかを見るか、小さな言語モデルで判定する必要がある |

## 4. Tokkio に入れる場合

pipecat 0.0.68 の部品（`customize_tokkio_japanese.py` の `TurnTaking`、`tokkio_speechcpp_stt.py`）を前提にした計画。コードを書いて確かめてはいない。

1. **VAD の停止を 0.2 秒にする。** `TurnTaking.vad_stop_secs: 0.6` → `0.2`（`SileroVADAnalyzer` の `stop_secs` に入る）。
2. **止まるたびにターン全体を書き起こし直す STT。** 今の `SpeechCppSTTService`（`SegmentedSTTService`）は区間ごとに 1 回送るだけ。ターンの音声を溜めて毎回全体を送る派生クラスを作る。区間ごとの文字起こしをつなぐ方法は安いが、「。」の付き方が変わるので、評価とは条件が違う（要確認）。
3. **判定してから LLM に渡す集約器。** 規則で「言い終わり」→ すぐ渡す。「まだ続く」→ 0.8 秒のタイマー、話が再開したら取り消し。
4. **取り消しと結合。** ターン確定後、アバターが声を出す前に話者が話し始めたら、LLM と TTS を止め、前半の文字起こしを次のターンにつなげる。2.5 節の「聞こえる切断」を今と同じにするのに必要。
5. **戻せるように設定で切り替える。** 実マイクで 10〜20 ターン確かめ、ace-controller のログで判定時間と切断を数える。

- 所要時間の見込み: 1〜4 の実装とテストで 1〜1.5 日、実マイク確認で半日。
- **ASR の要求が増える。** VAD 0.2 秒では、来訪者 1 ターンあたり平均 1.78 回（最大 4 回）、長い読み上げでは最大 12 回。Qwen3-ASR の区切りごとの時間は p90 188 ms で 0.2 秒に近く、`speech serve` は 1 件ずつ処理するので、要求が重なると待ちが出る。古い要求は捨てて最新だけ判定する作りにする。
- GPU 0 が休んでいると最初の数ターンの STT が 0.6〜0.8 秒かかる問題（10-17 の 7.5 節）は、今の方式と同じく残る。

## 5. 限界

- **自然な会話の日本語では試していない。** 来訪者の質問と難所は合成音声、FLEURS は読み上げ。言いよどみ、言い直し、相づち、雑音は含まれていない。
- 規則は丁寧な問いかけ（「〜ですか」「〜ください」）を前提に作った。くだけた話し方（「〜じゃん」「〜っしょ」）は「まだ続く」と判定されやすく、待ち上限まで待つ（遅くはなるが切らない側）。
- ASR 時間は GPU 1（描画と共有）で連続して送ったときの値。本番の GPU 0（vLLM と同居）での値は測っていない。
- **本番の ASR 設定では試していない。** 評価は `language=ja`・プロンプトなし。本番の `SpeechCppSTTService` はプロンプト「青嵐、SEIRAN」を送り、プロンプトの繰り返しを雑音として捨てる。プロンプトありで文末や句読点の付き方が変わるか、短い「はい」が捨てられないかは確かめていない。
- 「言い終わり」の判定に使ったのは最後の文字だけ。ASR が言いかけの語の頭を書き起こす（「それで、い」）と誤る。
- `strict` 規則と 2.5 節の T の幅は、結果を見てから足した分析。
