# TTS の感情表現: caption の強さ・絵文字・文体の比較（2026-10-18）

10/17 に caption（話し方の指示）を本番に入れたあとも「ロボットのよう」という感想だったので、残りの手段を本番と同じ文の切り方で比べた。この文書は条件と数値の記録。

**結論（2026-10-19）**: 試聴で D（全文の頭に 😊）を選んだ。unit に `IRODORI_TTS_STYLE_EMOJI=😊` を入れた（`IRODORI_TTS_SYMPATHY_EMOJI` は入れていない）。実験の文は本番の正規化後の文に同じ U+1F60A を付けたもので、本番で speech.cpp に渡る文と同じ。

## 実際に聞いた音声

- 10/17 23 時台の会話（controller ログ）で TTS に渡った 18 文。caption は 10/17 16:34 から反映済み（`/healthz` で確認）。
- 文は短い です・ます調: 「それは良かったですね。」「残念でしたね。」「次回の機会を楽しみにされると良いでしょう。」「オープンキャンパスは既に終了しています。」
- 返答の 1 文目は読点で切って先に合成する（`FirstClauseTextAggregator`）。例: 「私は複合材料、」「特にセラミックス複合材料の研究に長年取り組んできました。」
- 10/17 の比較では会話調の 2 文を 1 リクエストで送っていた。本番より文が長く、つながりのある音声で聞いていたことになる。

## 条件

- v4.1-Small、speech.cpp v0.8.7（Vulkan0 = nvidia-smi GPU 1、Unreal renderer と共有。本番サービスの GPU 0 には触れていない）、12 steps、`--threads 4`、短文の尺上限あり、サービスと同じ 16 kHz 後処理。
- 上のログの 10 文 × seed 1〜3。全構成に caption2（本番と同じ）を付けた。
- 絵文字は正規化の後に付けた。「ありがとうございました。」は固定の正規化で句点が外れるので、先に付けると別の文になる。絵文字は尺上限の推定（モーラ数）に影響しない。

| 構成 | 変えたところ |
| --- | --- |
| A | なし（本番と同じ） |
| B | `cfg_scale_instructions` 3 → 5 |
| C | `cfg_scale_instructions` 3 → 7 |
| D | 全文の頭に 😊（Irodori の「楽しげ」） |
| E | 全文の頭に 🫶（「優しく」） |
| F | 声ファイルを 10/17 の H（現行の参照＋雑談の録音、11 クリップ）に |
| G | 文を本人の口調に書き換え（TTS の設定は A と同じ） |
| H | G ＋ 絵文字（残念な話の 2 文は 🫶、他は 😊）＋ B の強さ |

G の書き換え例: 「それは良かったですね。」→「いやあ、それは良かったですね！」、「オープンキャンパスは既に終了しています。」→「オープンキャンパスは、もう終わってしまったんですよ。」（全文は `cases_soft.json`）。G・H は LLM の system prompt を変えた場合の見本で、TTS だけでは実現できない。

## 結果

| 構成 | 最初の音声（中央値） | 平均の長さ | F0 の揺れ（半音） | A より大きい組 | 本人らしさ（cosine） | CER > 0.2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A 本番 | 0.532 秒 | 2.72 秒 | 3.16 | 基準 | 0.626 | 1/30 |
| B cfg 5 | 0.528 秒 | 2.73 秒 | 3.10 | 18/30 | 0.625 | 0/30 |
| C cfg 7 | 0.529 秒 | 2.73 秒 | 3.16 | 18/30 | 0.623 | 1/30 |
| D 😊 | 0.536 秒 | 2.75 秒 | 3.02 | 8/30 | 0.619 | 0/30 |
| E 🫶 | 0.523 秒 | 2.76 秒 | 3.05 | 9/30 | 0.633 | 0/30 |
| F 混合の声 | 0.556 秒 | 2.72 秒 | 3.11 | 14/30 | 0.633 | 1/30 |
| G 柔らかい文体 | 0.665 秒 | 3.25 秒 | 3.08 | 14/30 | 0.628 | 0/30 |
| H G＋絵文字＋cfg 5 | 0.688 秒 | 3.28 秒 | 2.99 | 12/30 | 0.635 | 0/30 |

- **F0 の揺れでは差が出ない**。A との差の 95% 区間はどの構成も 0 をまたぐか、わずかに下（D・E）。短い文が多く、F0 では話し方の違いを測れていない。判断は試聴に任せる。
- **設定は効いている**。同じ文・seed の波形の差（A に対する平均絶対差の比、生の 48 kHz 出力の 30 組の平均）は cfg 5 で 0.22、cfg 7 で 0.37、😊 で 0.64、🫶 で 0.49。組ごとのばらつきは大きい（0.04〜1.34）。絵文字は長い文で尺も 0.04〜0.08 秒変わる。G・H は文が違うので比べていない。
  - 10/18 の版にあった「cfg 5 で 0.11〜0.18、cfg 7 で 0.23〜0.32、絵文字で 0.77〜1.02」は 3 組だけで計算した値だった（10/19 に全 30 組で計算し直して訂正）。
- **遅延は TTS 側の変更では変わらない**（0.52〜0.56 秒）。G・H は文が長いぶん遅い。
- **本人らしさは全構成で同等**（0.619〜0.635）。10/17 の 0.70 前後より低いのは、文が短いため。
- 読み誤り（Whisper で 2 割以上ずれ）: A の「ありがとうございました」seed 2 の後ろに別の音（「アルムチン」）、C の同じ文 seed 2 に「嬉しい。」、F の「残念でしたね。」seed 2 が「さあ、なんでしたね」。短文の後ろの余計な発話は 10/16 から知られている問題で、構成による差かは本数が少なく分からない。
- 笑い声・息などの言葉以外の音は Whisper に出ないので、絵文字の構成は耳で確かめる必要がある。

## 測り方の変更

- F0 は pyin の有声判定（voiced flag）を使った。10/17 と同じ「有声確率 > 0.5」だと、低い男性の声の短い文では 30 本中 18〜21 本で有声フレームが 40 未満になり、値が出なかった（`rescore_f0.py`）。10/17 の数値とは直接比べられない。

## 注意

- 絵文字を本番に入れる場合は、TTS サーバーで正規化の後に付ける。LLM に出させると、system prompt の「絵文字は出さない」と食い違い、字幕にも出る（`TTSTextFrame`）。
- 文の内容に合わない絵文字（終了の知らせに 😊）は不自然になりうるので、H では残念な話だけ 🫶 にした。本番で文ごとに選ぶ場合は規則が要る。
- G・H は LLM の system prompt の変更（docs/audits/llm-prompt-rules-2026-10-17.md の推奨 7）で、TTS の設定とは別の判断。
- 「こんにちは！今日は…」のように「！」で区切られた文は、本番では 2 回の TTS に分かれる。今回は 1 リクエストで合成した。
