# LFM3-1.7B は現行 LLM の置き換えになるか（2026-10-28）

## 結論

- 置き換えない。現行の Llama-3.1-Swallow-8B-Instruct-v0.5 を使い続ける。
- 決め手は品質。本番と同じ system prompt と参考情報で比べると、日本語の応答品質が Swallow-8B より明らかに低い。思考の文が本文に漏れる、自分を三人称で呼ぶ、長さの指示を守らない、など。配信エンジンを変えても重みは同じなので、この結果は変わらない。
- 配信経路は決め手ではない。Tokkio が要るのは OpenAI 互換の endpoint（`/health`、`/v1/models`、streaming の `/v1/chat/completions`）だけで、vLLM でなくてよい。LFM3 は vLLM・SGLang では未対応だが、llama.cpp の `llama-server` なら `master` で動く見込み（未実測）。
- 速さの利点は小さい。現行の出力は平均約 20 トークン（2026-10-17 監査）で、LLM の生成時間は応答遅延の主因ではない。
- 今の LLM の問題（temperature と max_tokens が送られていない、追質問が RAG に回らない）は、モデルを変えなくても直せる。`docs/audits/llm-prompt-rules-2026-10-17.md` の問題 1・2 が先。

## 対象と調べ方

- 対象: `LiquidAI/LFM3-1.7B`（2026-10-23 公開、1.73B、LFM Open License v1.0）。比較相手は本番の `Llama-3.1-Swallow-8B-Instruct-v0.5`（`infra/tokkio/.env` の `TOKKIO_LLM_MODEL`）。
- モデルカード、config、chat template、LICENSE は Hugging Face から直接読んだ。vLLM の対応は GitHub の `main` の `vllm/model_executor/models/registry.py` と PyPI の最新版（0.32.0、2026-10-18）で確かめた。
- 実測は transformers 5.21.0（`trust_remote_code`）、RTX 6000 Ada 1 枚（GPU1）、bf16、バッチ 1。評価環境と出力は `/data/ACE/llm-eval/`（`scripts/`、`prompts.json`、`out_lfm3.json`、`out_swallow.json`）。
- プロンプトは本番と同じ作り方にした。system prompt は `infra/tokkio/customize_tokkio_japanese.py` の `OpenAILLMContext.prompt`、参考情報は `infra/rag/local_rag.py` の `search_index`（top_k 3）と `format_hits_for_prompt_with_sources`（2800 字）で `/data/ACE/data/rag/local/local_rag.sqlite` から作った。10 問 × 2 回。
- サンプリング: LFM3 はカード推奨の `temperature=0.1, top_k=50, repetition_penalty=1.1`、`enable_thinking=False`。Swallow は本番と同じ同梱の generation config（`temperature=0.6, top_p=0.9`）。
- 本番の vLLM・Tokkio には触れていない。`.env` も変えていない。

## 根拠

### 1. 配信経路（vLLM 以外なら道はある）

| 経路 | LFM3 対応 | 確認したもの |
|---|---|---|
| vLLM | なし | `main` の registry に `Lfm3ForCausalLM` がない（`Lfm2*` だけ）。`lfm3.py` は 404 |
| SGLang | レビュー中 | FP8 カードに「sgl-project/sglang#46858 で review 中」とある |
| llama.cpp | `master` で対応済み | `src/llama-arch.cpp` に `LLM_ARCH_LFM3` がある（2026-10-28 確認）。最新リリース（v0.7.0）に入っているかは未確認 |
| transformers | カスタムコードのみ | 5.21.0 にも `lfm3` はない。5.12.1 では同梱コードが import に失敗し、5.21.0 で動いた |

- 本番の vLLM は 0.9.2（2026-10-17 監査）。LFM3 に限らず新しい構造のモデルは、まず vLLM の image 更新が要る。
- vLLM の Transformers backend で動くかは試していない。畳み込み層を持つ構造なので、動かない可能性が高いと考えるが未確認。

### 2. 日本語の応答品質（実測、10 問 × 2 回）

| 指標 | LFM3-1.7B | Swallow-8B |
|---|---|---|
| 応答文字数の中央値（指示は 40〜60 字） | 137.5 | 62 |
| 100 字を超えた応答 | 12 / 20 | 4 / 20 |
| 思考や指示の復唱が本文に出た | 3 / 20 | 0 / 20 |
| 自分を「香川豊さんは」「香川豊学長は」「学長が」と三人称で呼んだ（目視。資料や指示の引用は除く） | 4 / 20 | 0 / 20 |
| 禁止した「公式サイトで確認」の定型文 | 3 / 20 | 2 / 20 |
| `<think>` タグの出力 | 0 / 20 | — |

LFM3 の典型的な失敗:

- 雑談「今日はいい天気ですね。」→「参考情報によると、ユーザーが「香川先生」…と呼んでいる場合、それは自分への呼びかけとして扱います。まず、天気の感想に答える必要がありますが…」。`<think>` タグは出ないが、推論の文がそのまま本文に出る。TTS がこれを読み上げる。
- 「CMCって何ですか。」→「私はセラミックス複合材料（CMC）の略で…」。主語が崩れる。
- 「オープンキャンパスはいつありますか。」→ 1 回目は「開催予定」と答え、終了済みの印を無視した。2 回とも 150 トークン超。

Swallow-8B の失敗（既知の問題と同じ）:

- 「先生の好きな食べ物は何ですか。」→ 1 回目に「秋の味覚であるきのこ料理」と作り話をした。temperature 0.6 のまま（監査の問題 2）。
- 追質問「いつやるか教えてほしいです。」（参考情報なし）→「2024年のオープンキャンパスは、8月3日、4日、5日に開催されました。」と作り話をした（監査の問題 1）。

LFM3 は根拠のない質問では「確認されていません」と答える傾向があった。カードの AA-Omniscience non-hallucination 92.93 と合う。ただし知識の正答率は 7.07 と低い。

### 3. 速さ

| 指標（transformers、バッチ 1） | LFM3-1.7B | Swallow-8B |
|---|---|---|
| 最初のトークンまでの時間の中央値 | 0.049 s | 0.227 s |
| 応答全体の時間の中央値 | 1.78 s | 1.12 s |
| 入力トークン数の平均 | 1060 | 1188 |
| 出力トークン数の平均 | 89 | 52 |

- 最初のトークンは LFM3 が速い。ただし応答が長いので、全体では Swallow のほうが短い。
- transformers は Python の処理が支配的で、vLLM での値とは違う。順位の目安としてだけ使う。
- 日本語のトークン効率は LFM3 が約 1 割よい（system prompt 1033 字が 649 トークン、Swallow は 717 トークン）。

### 4. カードの性能表は用途が違う

- 表はエージェント、tool calling、コード、英語の指示追従が中心。日本語のベンチマークも人物対話のベンチマークもない。
- カード自身が「知識が要る用途では retrieval を使う」「複雑な多段推論には勧めない」と書いている。
- 思考モードは既定で有効。chat template は `enable_thinking=False` のとき `<think></think>` を先に埋める。カードは「無効化は不安定なことがある」と書いており、上の雑談の例がそれに当たる。

### 5. OpenAI 互換 endpoint として動かした結果

- llama.cpp のビルドは自動モードに拒否された。`transformers serve` は同梱カスタムコードのモデルを読めない（`AttributeError: module transformers has no attribute Lfm3ForCausalLM`）。
- そこで transformers で動かす小さなサーバーを作った: `/data/ACE/llm-eval/scripts/lfm3_openai_server.py`（`/health`、`/v1/models`、streaming の `/v1/chat/completions`、`stream_options.include_usage`）。リクエストにサンプリングの指定がなければ、checkpoint の generation config（temperature 0.1、top_k 50、repetition_penalty 1.1）を使う。`enable_thinking=False` を既定にした。バッチ 1 で、試験用。
- `infra/llm/check_llm_endpoint.py --base-url http://127.0.0.1:8014/v1 --model lfm3-1.7b` は health・models・stream すべて ok。初回の TTFT は 2.3 s（Triton カーネルの初回コンパイル）。
- 本番の Tokkio と同じ送り方（stream、サンプリング指定なし）で 10 問 × 2 回: TTFT の中央値 0.054 s、応答全体 1.55 s、文字数の中央値 117、100 字超え 13 / 20。
- 品質の傾向は transformers 直のときと同じ。雑談で思考の文が漏れ、「CMCって何ですか」で「私はセラミックス複合材料（CMC）の略で」と答えた。新たに「富士山の高さは4,369メートルです」という誤りも出た。

## 未確認
