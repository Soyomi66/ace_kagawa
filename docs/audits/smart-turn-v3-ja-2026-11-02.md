# Smart Turn v3 で話し終わりの判定を速くできるか（日本語、オフライン）

実施日: 2026-11-02 / 対象: `ace_kagawa`

目的: 応答を速くするため、VAD の 0.6 秒の沈黙待ちを、Smart Turn v3（声の抑揚から「言い終わったか」を判定するモデル）と VAD 0.2 秒の組み合わせに置き換えられるかを確かめる。本番の Tokkio・controller には触れていない。

## 結論

**Smart Turn v3.2 は日本語では使えない。** 文の途中の間（ま）を「言い終わり」と判定してしまい、発話を途中で切る割合が今の VAD 0.6 秒の 2〜5 倍になる。

| 音声 | 方式 | 文の途中で切った発話 | 言い終わりから判定まで |
| --- | --- | ---: | ---: |
| FLEURS 650 本（実音声の読み上げ） | 今の VAD 0.6 秒 | 16.2% | 0.61 秒 |
| | Smart Turn（CPU 版）＋VAD 0.2 秒 | **57.4%** | 0.19 秒（切られなかった発話のうち 42%）。残りは待ち上限まで |
| | Smart Turn（GPU 版、fp32）＋VAD 0.2 秒 | 51.1% | 同上（49%） |
| 来訪者の質問 160 本（合成音声） | 今の VAD 0.6 秒 | 6.9% | 0.61 秒 |
| | Smart Turn（CPU 版）＋VAD 0.2 秒 | **36.2%** | 0.19 秒（62%） |
| | Smart Turn（GPU 版）＋VAD 0.2 秒 | 24.4% | 0.19 秒（74%） |

- しきい値 0.5、「まだ続く」と判定したときの待ち上限 0.6 秒。しきい値を 0.7 にしても、待ち上限を 1.0 秒や 3.0 秒にしても、切る割合はほとんど変わらない（2 節）。
- **言い終わりはよく当てる。誤りは文中の間に集中している。** 文末を「言い終わり」と判定できたのは FLEURS で 636/650、来訪者で 154/160。一方、文中の間（0.2 秒以上）を「言い終わり」と判定したのは FLEURS で 818 か所中 617 か所（75%）、来訪者で 125 か所中 52 か所（42%）。しきい値を変えても組み合わせを変えても救えないのはこのため。
- 切れた例:「東京工科大学の｜八王子キャンパスへの行き方を…」（確率 0.96）、「医療保健学部の｜看護学科について…」（0.96）。助詞「の」で終わる、文法上は明らかに途中の箇所。日本語の句の終わりで音程が下がるのを、文末と取り違えていると見られる。
- **VAD を 0.3〜0.5 秒にして Smart Turn を足す中間案も、今より悪い。** VAD 0.4 秒＋Smart Turn で判定は約 0.40 秒になるが、途中で切る割合は来訪者 17%、FLEURS 29%（今は 7% / 16%）。VAD 0.5 秒にすると切る割合は今とほぼ同じかやや多い（来訪者 9〜13%、FLEURS 19〜21%）で、速くなるのは 0.1 秒だけ。

## 1. 方法

### 1.1 pipecat と同じ動かし方

| 部分 | 再現した動き |
| --- | --- |
| VAD | Silero VAD（ONNX）、512 サンプル窓、確信度 0.7 以上を音声、開始 0.2 秒。状態は約 2 秒ごとに静かなところでリセット（pipecat と同じ）。音量の判定（min_volume 0.6）は再現していない |
| Smart Turn を呼ぶ時点 | VAD が 0.2 秒の沈黙で停止するたび |
| Smart Turn に渡す音声 | 話し始めの 0.7 秒前（pre_speech 0.5 秒＋VAD 開始 0.2 秒）からその時点まで。最後の 8 秒、Whisper の log-mel |
| 「まだ続く」のとき | 話が再開すれば続ける。沈黙が待ち上限に達したら終わり（pipecat の `stop_secs`。既定は 3 秒） |

「途中で切った」は、最後の発話区間より前で区切りが確定したもの。アバターが質問の前半だけで答え始める状況に当たる。

### 1.2 実装の確認

公式テストデータ（`pipecat-ai/smart-turn-data-v3.2-test`）の日本語 834 本で、公式発表と同じ正解率が出ることを確かめた（CPU 版 96.16%、GPU 版 97.12%）。したがって上の結果は、モデルが日本語の音声でこう振る舞うということで、こちらの実装の誤りではない。

**ただし公式の日本語 834 本は、すべて Google の TTS（Chirp 3）の合成音声だった**（`synthetic: true`、データセット `chirp3_1`）。末尾の無音も中央値 25 ms と短く、pipecat が実際に渡す約 0.2 秒の無音つきの音声とは条件が違う。人の声の日本語での精度は公表されていない。

### 1.3 評価した音声

| セット | 中身 | 文中の間（0.2 秒以上） |
| --- | --- | ---: |
| FLEURS ja_jp test | 650 本、人の読み上げ、平均 13 秒 | 818 か所 |
| 来訪者の質問 | 160 本、Irodori の合成音声（4 話者）、10/17 の ASR 評価と同じ | 125 か所 |
| 難所セット | Irodori で合成した言いかけ 15 文（「〜けど、」「えっと、」「〜の」）と、短い返事 15 文（「はい。」「いいえ。」）× 4 話者 | — |

## 2. 詳細

### 2.1 FLEURS（実音声）

| 方式 | 途中で切った | 判定まで p50 | 言い終わりをモデルが即判定 |
| --- | ---: | ---: | ---: |
| VAD のみ 0.3 秒 | 47.8% | 0.29 秒 | — |
| VAD のみ 0.4 秒 | 35.1% | 0.38 秒 | — |
| VAD のみ 0.5 秒 | 20.9% | 0.51 秒 | — |
| **VAD のみ 0.6 秒（今）** | **16.2%** | 0.61 秒 | — |
| VAD のみ 0.8 秒 | 11.2% | 0.80 秒 | — |
| Smart Turn CPU 版、しきい値 0.5、上限 0.6 秒 | 57.4% | 0.19 秒 | 42% |
| Smart Turn CPU 版、しきい値 0.7、上限 1.0 秒 | 55.8% | 0.19 秒 | 43% |
| Smart Turn GPU 版、しきい値 0.5、上限 0.6 秒 | 51.1% | 0.19 秒 | 49% |
| Smart Turn GPU 版、しきい値 0.7、上限 1.0 秒 | 47.4% | 0.19 秒 | 52% |

FLEURS は Wikipedia 文の読み上げで、読点ごとに間が入る。来訪者の短い問いかけより間が多いので、VAD のみでも切る割合が高い。

| VAD のみ 0.4 秒 | 35.6% | 0.38 秒 | — |
| VAD のみ 0.5 秒 | 15.6% | 0.51 秒 | — |
| **VAD のみ 0.6 秒（今）** | **6.9%** | 0.61 秒 | — |

| Smart Turn GPU 版、しきい値 0.5、上限 0.6 秒 | 24.4% | 0.19 秒 | 74% |

### 2.3 難所セット（合成音声）

| 判定 | CPU 版 | GPU 版 |
| --- | ---: | ---: |
| 言いかけ（「〜けど、」など）を「言い終わり」と誤判定（アバターが割り込む） | 14/59（24%） | 13/59（22%） |
| 短い返事（「はい。」など）を 0.2 秒で「言い終わり」と判定 | 37/60（62%） | 33/60（55%） |

- 誤判定した言いかけ:「東京工科大学への行き方なんですけど、」「入試のことで、ちょっと」「えーと、メディア学部の」「青嵐を使うには、」「質問なんですけど、」など。
- 「言い終わり」と判定できなかった短い返事:「はい。」（0.05）、「そうです。」（0.02）、「なるほど。」（0.02）、「いいえ。」など。これらは待ち上限まで待つので、速くならない。
- 「えっと、」1 本（f_young）は VAD が音声と判定しなかった。

### 2.4 中間案（VAD 0.3〜0.5 秒で止まったときだけ Smart Turn に聞く）

| 方式 | 来訪者: 途中で切った / 判定 | FLEURS: 途中で切った / 判定 |
| --- | ---: | ---: |
| 今（VAD 0.6 秒） | 6.9% / 0.61 秒 | 16.2% / 0.61 秒 |
| VAD 0.3 秒＋Smart Turn（CPU、上限 0.6 秒） | 25.6% / 0.31 秒 | 41.8% / 0.30 秒 |
| VAD 0.4 秒＋Smart Turn（CPU、上限 0.6 秒） | 16.9% / 0.40 秒 | 28.9% / 0.40 秒 |
| VAD 0.4 秒＋Smart Turn（GPU、上限 0.8 秒） | 11.9% / 0.42 秒 | 26.0% / 0.40 秒 |
| VAD 0.5 秒＋Smart Turn（CPU、上限 0.8 秒） | 9.4% / 0.51 秒 | 20.2% / 0.50 秒 |

- 判定は平均。Smart Turn の確率は 0.2 秒で止まった時点のものを流用した近似。実際には末尾の無音が長くなるが、無音 0.2 秒ありと無音なしで切る割合がほぼ同じ（FLEURS で 57.4% と 56.9%）なので、近似の影響は小さい。
- VAD 0.4 秒のみ（来訪者 35.6%）と比べると Smart Turn は誤りを半分に減らすが、今の 0.6 秒には及ばない。

### 2.5 推論時間

| モデル | CPU 1 スレッド | 2 スレッド | 4 スレッド |
| --- | ---: | ---: | ---: |
| smart-turn-v3.2-cpu（int8、8.7 MB） | 69 ms | 75 ms | 109 ms |
| smart-turn-v3.2-gpu（fp32、32 MB、CPU で実行） | 90 ms | 96 ms | 110 ms |

特徴量（transformers の WhisperFeatureExtractor）込み、8 秒の入力、p50。計測時の load average は約 8 で、スレッドを増やすと遅くなった。

## 3. 限界

- **自然な会話の日本語では試していない。** 使ったのは合成音声（Irodori、公式テストの Chirp 3）と読み上げ（FLEURS）。ただし誤りは「〜の｜」のような文法上明らかな途中で、確率 0.96 のように強く出ているので、実マイクで結果が逆転するとは考えにくい。確かめるなら、途中で一度間を置いた発話を 10 本ほど録音すれば `scripts/turn_eval.py` で数分で判定できる。
- pipecat の音量判定（min_volume）と、0.0.68 と最新版の VAD の細かな違いは再現していない。
- 待ち上限（`stop_secs`）は 0.6〜3.0 秒で調べた。
