# speech.cpp の ASR と現行 Riva ASR の比較

実施日: 2026-10-17 / 対象: `ace_kagawa`

speech.cpp v0.8.10 が対応する日本語 ASR 4 種と、Tokkio 本番の Riva ASR（`conformer-unified-ja-JP` ストリーミング）を、同じ音声で比べた。

- Riva には本番の ace-controller と同じ設定（boost 語「青嵐」「SEIRAN」、句読点なし、`enable_vad_endpointing`）で gRPC ストリーミングした。
- speech.cpp には、pipecat の `OpenAISTTService` と同じ呼び方（openai SDK の `audio.transcriptions.create`）で `speech serve` に送った。
- 計測は Tokkio 稼働中・会話なしの状態で行った。

> **2026-10-17 追記（この調査を受けた変更）**
> 1. `TurnTaking` を 0.5 秒 / 250 ms / 0.2 秒から 0.8 秒 / 500 ms に戻した（ユーザー指示、5 節）。
> 2. 音声認識を **speech.cpp の qwen3-asr-1.7b（prompt「青嵐、SEIRAN」）に切り替えた**（ユーザー判断）。集約待ちは 0.05 秒にした（7 節）。Riva はクラスタに残してあり、`Pipeline.stt_processor` を戻せば元に戻る。
> 3. VAD を 0.6 秒に下げて試している（23:08〜、ユーザー判断）。
> 4. いずれも稼働中の controller に反映済み。実マイクでの確認はまだ。

## 結論

**qwen3-asr-1.7b に prompt「青嵐、SEIRAN」を渡す構成が最も正確だった。** 来訪者の質問セット（合成音声）で CER 3.3%、「青嵐」を 16 回中 16 回正しく書いた（Riva は boost 語に入れていても 0 回）。FLEURS（実際の人の読み上げ）でも CER 5.3% で最良だった。GPU メモリは 2.3 GB（Riva の Triton は 3.3 GB）。

ただし次の 2 点が要る。

- **雑音・無音への出力を捨てる処理。** prompt ありの Qwen3-ASR は、無音・雑音 6 種すべてに「青嵐、SEIRAN。」と書いた（6 節）。prompt だけの文字起こしは捨てるようにした。
- **prompt は数語にとどめる。** 18 語の一覧を渡すと、一覧をそのまま書き出す回が出た（1.7B で 160 回中 4 回、0.6B で 10 回）。

FLEURS の同じ 100 発話では、Riva 500 ms が CER 12.6%、qwen3-asr-1.7b が 6.1% だった（長い文の途中の間で Riva の確定結果が分かれるため）。

速さと軽さを優先するなら parakeet-tdt_ctc-0.6b-ja（CER 4.9%、認識 27 ms、0.7 GB）。語彙を指定する仕組みがなく、「青嵐」は書けない。

**別件として、今日 250 ms に下げていた Riva の `asr_stop_history_ms` が認識を大きく壊していた（5 節）。** 短い間で発話が細切れの確定結果になり、切れ目の文字が落ちる。今日の実マイク会話でも「こんにちは」→「お」「にちは」、「先生のご専門は何でしょうか」→「生のご専門は何」「でしょうか」と出ていた。

- 「青嵐」は「青嵐」または「SEIRAN」と書いた回を漢字、「せいらん / セイラン」をかな、それ以外（「生卵」「精卵」「性乱」「セーラン」など）を誤りとした（4 文 × 4 話者）。
- 固有名詞は 40 文に入れた 41 語（東京工科大学、八王子みなみ野、蒲田、セラミックス基複合材料、炭化ケイ素、NEDO など）を、表記どおりに書けた割合。

- 認識 p50 は GPU 0 で 1 発話（平均 3.6 秒＋前後の無音）を送ってから結果が返るまで。VRAM は nvidia-smi のプロセス使用量。Riva は Triton プロセス（日本語 ASR だけを載せている）の値。
- 来訪者セットは文頭に 0.8 秒の無音を足した条件（2.3 節）。

## 1. speech.cpp v0.8.10 の ASR 対応

（2026-10-17 時点の最新リリース。v0.8.8〜0.8.10 の差分は Qwen3-ASR の高速化、ggml 0.27、表示まわり）

| 名前 | 元モデル | 言語 | ファイル（既定 Q8_0） | 語彙の指定 |
| --- | --- | --- | --- | --- |
| `parakeet-tdt_ctc-0.6b-ja` | nvidia/parakeet-tdt_ctc-0.6b-ja | ja | 0.66 GB | なし |
| `reazonspeech-v2` | reazon-research/reazonspeech-nemo-v2 | ja（句読点つき） | 0.66 GB | なし。`decoding` で beam / greedy |
| `qwen3-asr-0.6b` | Qwen/Qwen3-ASR-0.6B | 30 言語 | 0.84 GB | `prompt` |
| `qwen3-asr-1.7b` | Qwen/Qwen3-ASR-1.7B | 30 言語 | 2.18 GB | `prompt` |
| `parakeet-tdt-0.6b-v3` | nvidia/parakeet-tdt-0.6b-v3 | 欧州 25 言語（英語を含む） | 1.26 GB（F16） | なし |
| `silero-vad` | Silero VAD v6.2 | — | 1.2 MB | — |

- 上流の公表値（Common Voice 8.0 日本語 test 4,483 発話、Q8_0）: parakeet-ja CER 7.93%、reazonspeech beam 12.04%、qwen3-asr-0.6b 11.89%、1.7b 9.49%。
- **どのモデルもストリーミング（途中経過）はない。** 1 回の要求で音声全体を認識する。`speech serve` の `/v1/realtime` は VAD で区切ってから認識するもので、こちらにも約 0.7 秒の無音待ちがある。
- `speech serve` は OpenAI 互換の `POST /v1/audio/transcriptions` を持ち、認識モデルを 1 つだけ載せる。Qwen3-ASR は要求ごとの `language`（`ja` / `en`）で英語モードにも使える。
- FastConformer 系に `prompt` を送ると 400（`unsupported_parameter`）。`temperature` などの未知のフィールドもすべて 400（pipecat の `OpenAISTTService` は既定では送らない）。
- Tokkio 側は、pipecat 0.0.68 に同梱の `OpenAISTTService`（`SegmentedSTTService` の派生）を少し変えた派生クラスで使えた（7 節）。

## 2. 方法

### 2.1 評価音声

| セット | 中身 | 用途 |
| --- | --- | --- |
| FLEURS ja_jp test | 650 発話（実音声の読み上げ、平均 13.1 秒、16 kHz） | 一般的な精度 |
| 来訪者の質問 | 40 文 × 4 話者 = 160 発話（平均 3.6 秒） | 固有名詞・短い問いかけ・遅延 |

- 来訪者の質問は、大学・青嵐・香川先生の研究・入試などの問いかけと、「はい、お願いします。」「こんにちは。」などの短い返事。文は `scripts/domain_sentences.json`。
- 音声は Irodori-TTS v4.1-Small（speech.cpp、voice `none`）で合成した。caption で 4 人の話者（20 代男性・50 代男性・20 代女性・40 代女性）にした。基本周波数の中央値は約 150 / 150 / 235 / 213 Hz。
- TTS の読み違いを避けるため、固有名詞はかなで入力した（「せいらんについて教えてください。」）。採点は漢字の参照文（「青嵐について教えてください。」）で行った。
- 合成音声は 48 kHz → 16 kHz をポリフェーズフィルターで変換した。最初はフィルターなしで間引いてしまい、折り返し雑音が乗ったので作り直した（作り直す前の結果は使っていない）。

### 2.2 システムと設定

- **Riva**: 本番 Tokkio の `riva-speech`（Riva 2.19、Triton に日本語 ASR だけを載せている）へ、本番の nvidia-pipecat `RivaASRService` と同じ `StreamingRecognitionConfig` で gRPC ストリーミングした。
  - 20 ms のフレームを実時間で送り、最後に 2 秒の無音を足した。発話ごとに新しいストリームにした。
  - 「最後の確定結果が届いた時刻 − 話し終わりの時刻」を測った。話し終わりは、最大フレームから −34 dB を上回る最後の 10 ms とした。
- **speech.cpp**: `speech serve MODEL --device Vulkan1 --threads 4`（GPU 0 = Riva・vLLM・Irodori と同じ GPU）で起動した。
  - 発話の後ろに 0.5 秒の無音をつけた WAV を、openai SDK で `model`・`language=ja`・`prompt` つきで送った（pipecat の `OpenAISTTService._transcribe` と同じ引数）。
  - FLEURS は GPU 1（描画と共有）で測ったので、FLEURS の認識時間は参考値。
- **スレッド数**: 既定（全コア）だと、混んでいる CPU（16 論理 CPU）と奪い合い、load average 45、22 秒の音声に 20〜30 秒かかった。`--threads 2〜4` で 0.07〜0.09 秒になった。以後の計測は 4 スレッド。

### 2.3 文頭の無音

pipecat の `SegmentedSTTService` は、VAD が発話開始を検出する前の最大 1 秒を一緒に送る。そのため来訪者セットは文頭に 0.8 秒の無音を足した条件を本命にした（合成音声そのものの文頭無音は中央値 30 ms）。

| 構成 | 文頭無音なし | 0.8 秒 |
| --- | ---: | ---: |
| Riva 250 ms / 500 ms | 22.7% / 5.3% | 22.7% / 5.3% |
| qwen3-asr-1.7b＋prompt | 3.6% | 3.3% |
| qwen3-asr-1.7b | 5.3% | 4.6% |
| parakeet-ja | 5.6% | 4.9% |
| reazonspeech-v2 beam / greedy | 15.0% / 15.5% | 7.2% / 7.3% |
| qwen3-asr-0.6b | 7.3% | 7.2% |

reazonspeech は文頭の無音が短いと最初の語を落とした（「青嵐について」→「について」）。

## 3. 来訪者セットの補足

- 話者別の CER（qwen3-asr-1.7b＋prompt）: 20 代男性 3.4%、50 代男性 3.2%、20 代女性 2.9%、40 代女性 3.5%。他の構成でも男女で大きな差はなかった（reazonspeech greedy だけ女性で 8〜10%）。
- 全構成に共通の誤り: 「医療保健学部」→「医療保険学部」、「八王子みなみ野」→「八王子南の / 南野」、「AO 入試」→「英語入手 / 栄養入試 / o 入試」。
- qwen3-asr-1.7b は数字の書き方が prompt で変わった（prompt なし「二千二十六年度」、あり「2026年度」）。
- Riva は boost（score 8.0）を指定していても「青嵐」を一度も書かなかった。boost を外しても、160 発話すべてで boost ありと同じ文字起こしになった。この Riva の構成では boost が効いていない。

| --- | ---: | ---: | ---: | ---: |
| qwen3-asr-1.7b | **5.32%** | **3.20%** | 0.59 秒 | 6.06% / 3.74% |
| parakeet-ja | 6.06% | 4.06% | 0.07 秒 | 6.33% / 3.98% |
| reazonspeech-v2 beam | 6.21% | 3.77% | 0.28 秒 | 6.29% / 3.74% |
| reazonspeech-v2 greedy | 6.59% | 4.20% | 0.10 秒 | 5.95% / 3.84% |
| qwen3-asr-0.6b | 8.43% | 5.11% | 0.52 秒 | 8.87% / 5.72% |
| Riva 500 ms | — | — | — | 12.6% / 8.95% |

## 5. Riva の `asr_stop_history_ms` 250 ms

### 5.1 実音声（今日の本番ログ）

2026-10-17 15:28〜（250 ms・VAD 0.5 秒に変えた直後の実マイク確認）の ace-controller ログには、確定結果が 25 件あった。

```text
[i] [i] [お] [にちは] [そう] [うん] [と] [今日は] [何のお話をしよう] [うかなって] [y] [そうですね] [あ] [あの]
[お名前も] [いい] [しいです] [東京工科大学への行き方] [ください] [a] [s] [生のご専門は何] [でしょうか] [これいい] [y]
```

- 「こんにちは」→「お」「にちは」、「しようかなって」→「しよう」「うかなって」、「先生のご専門は」→「生のご専門は」、「行き方（を教えて）ください」→「行き方」「ください」のように、切れ目の文字が落ちている。
- 25 件中 5 件（i、y、a、s、y）は雑音への出力だった。
- 250 ms にする前のログは残っていないので、500 ms のときに同じだったかは実音声では確かめられていない。

### 5.2 合成音声での再現

同じ発話（「せいらんについて教えてください」）を Riva に送ると、確定結果は次のようになった。

| stop_history | 確定結果 |
| --- | --- |
| 250 ms | 「生卵について」「え」「てください」 |
| 500 ms | 「生卵について」「教えてください」 |
| 800 ms | 「生卵について教えてください」 |

来訪者セット全体では、250 ms で 96% の発話が複数の確定結果に分かれ、CER 22.7%。500 ms では 71% が分かれ、CER 5.3%。800 ms では 14% が分かれ、CER 4.7%。

### 5.3 500 ms に戻すなら VAD も 0.8 秒

500 ms のまま VAD を 0.5 秒にすると、160 発話中 87 発話で最後の確定結果が VAD 停止より後に届いた。そのうち 56 発話は確定結果が複数あったので、VAD 停止の時点で途中までの文が LLM に送られる。VAD 0.6 秒では 25 / 18、0.8 秒では 2 / 2。そこで 0.8 秒 / 500 ms に戻した（README の「Riva の値は VAD の値より十分小さく」に合う組み合わせ）。

## 6. 雑音・無音と prompt

無音 1 秒、白色雑音（−40 dB・−25 dB）、褐色雑音 2 秒、息のような短い雑音、遠くの話し声（−30 dB）の 6 種を送った。

| 構成 | 無音 | 白色 −40 | 白色 −25 | 褐色 | 息 | 話し声 |
| --- | --- | --- | --- | --- | --- | --- |
| qwen3-asr-1.7b＋prompt | 青嵐、SEIRAN。 | 青嵐、SEIRAN。 | 青嵐、SEIRAN。 | 青嵐、SEIRAN。 | 青嵐、SEIRAN。 | 青嵐、SEIRAN。 |
| qwen3-asr-0.6b＋prompt | 同上 | 同上 | 同上 | 同上 | 同上 | 同上 |
| qwen3-asr-1.7b | はい。 | はい。 | はい。 | はい。 | （空） | いい。 |
| parakeet-ja | どうぞ。 | どうぞ。 | どうぞ。 | うん。 | フッ。 | うん? |
| reazonspeech-v2 | うん。 | これ。 | あ! | はい。 | あ! | えっ? |
| Riva 250 / 500 ms | （空） | （空） | a | an | h | え |

- どのモデルも、VAD が雑音を発話と判定すれば何かを書く。Riva でも本番ログに出ている。
- prompt ありの Qwen3-ASR は必ず prompt そのものを書くので、「prompt と同じ文字起こしは捨てる」だけで全 6 種を落とせる（`tokkio_speechcpp_stt.py`）。controller の pod から試すと、雑音・無音は空文字になった。
- prompt なしの「はい。」は本当の返事と区別できないので、prompt なしで使うなら別の対策が要る。
- 短い prompt でも、0.6B は「総合型選抜と AO 入試は」を「総合型戦拔と SEIRAN は」と書いた回が 1 回あった（1.7B は 0 回）。

## 7. Tokkio への組み込み（実施済み）

| 場所 | 中身 |
| --- | --- |
| `infra/asr/` | `ace-speechcpp-asr.service`（port 8024、GPU 0、4 スレッド、モデルはパス固定）、起動ラッパー（起動後に nvidia-smi で GPU UUID を照合）、インストーラー、README |
| `infra/tokkio/tokkio_speechcpp_stt.py` | pipecat の `OpenAISTTService` の派生。鍵なし、タイムアウト 10 秒・再試行なし（SDK 既定は 600 秒・2 回）、prompt だけの文字起こしを捨ててログに出す |

- `model` はサーバーが返す id（`Qwen3-ASR-1.7B`）でないと 404 になる。カタログ名ではない。
- 発話ごとに 1 回、VAD の停止後に結果が届くので、集約待ちは 0.05 秒にした。
- 途中経過（interim）は出なくなった。UI のユーザー発話は話し終わってから表示される。
- 戻し方: `Pipeline.stt_processor: "RivaASRService"`（集約待ちも 0.2 秒に）→ `prepare_tokkio_workspace.py` → `manage_tokkio.sh sync-controller`。
- unit は `enable` していない（Irodori と同じ）。ホスト再起動後は `manage_tokkio.sh start` が起動する。別の方法で Tokkio を起動すると ASR がなく、要求ごとに `APIConnectionError` がログに出てユーザーには無反応になる。`status` で分かる。

## 7.5 実マイクでの確認（2026-10-17 23:19〜23:21、VAD 0.6 秒）

ace-controller のログから 10 ターンを集計した（青嵐・短い「はい」・雑音は含まれていない）。

| 項目 | 中央値 | 範囲 |
| --- | ---: | ---: |
| STT（speech.cpp の処理） | 0.07 秒 | 0.04〜0.80 秒 |
| 文字起こし → TTS 開始（LLM の最初の句） | 0.23 秒 | 0.06〜0.39 秒 |
| TTS の最初の音声まで | 0.38 秒 | 0.20〜0.84 秒 |
| VAD 停止 → 最初の音声 | 1.06 秒 | 0.46〜1.40 秒 |
| 同上（4 ターン目以降） | 0.74 秒 | 0.46〜1.19 秒 |

- 話し終わりから最初の声までは、VAD の 0.6 秒を足して約 1.34 秒（4 ターン目以降）。Riva 250 ms・VAD 0.5 秒の 15:28 の確認（0.5 秒＋中央値 0.94 秒 ≒ 1.44 秒、8 返答）と同程度で、文字落ちはなくなった。返答数が少ないので差は誤差の範囲。
- **最初の 3 ターンだけ STT が 0.61〜0.80 秒かかった。** サーバー側の処理時間も同じだった。GPU 0 は 2 秒使われないとクロックを 210〜375 MHz まで落とし、その状態からの認識は 0.25〜0.44 秒かかる（同じ音声で、クロックが上がっていれば 0.09 秒）。ベンチマークは要求を連続で送っていたので、この影響を含まない。会話の途中では A2F などで GPU 0 が動いているためか、4 ターン目以降は 0.05〜0.08 秒だった。最初の 3 ターンが 0.6 秒を超えた理由は特定できていない。
- 発話が 2 回に分かれたのは 2 回（「そうね、オープンキャンパスのあの。」「いつやるか教えてほしいです。」など）。どちらも間が約 1.3〜1.6 秒あり、VAD 0.8 秒でも分かれる長さだった。
- 誤認識と思われるもの: 「先行は何をしていますか」（「先生は」か）。雑音として捨てた文字起こしは 0 件。

## 8. 制約・未確認

- **来訪者セットは合成音声。** 実際のマイク（部屋の反響、遠い話者、言いよどみ）では確かめていない。切り替え後の実マイク確認が要る。
- 話し終わりから LLM までの時間は、集約器のコードからの計算で、実測ではない。
- 同時に複数の会話がある場合は測っていない。`speech serve` は 1 モデルにつき要求を 1 件ずつ処理する（今の Tokkio は同時 1 会話）。
- FLEURS の speech.cpp の認識時間は GPU 1（描画と共有）での値。Riva の FLEURS は 100 発話だけ。
- Riva 250 ms の最初の 5 発話は、こちらの CPU 過負荷中に測っていたので取り直した（文字起こしは同じ、遅延だけ差し替え）。
- 英語（parakeet-tdt-0.6b-v3、Qwen3-ASR の `en`）は測っていない。
