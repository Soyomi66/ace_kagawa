# LLM プロンプト・ルール監査と参照音声の話し方（2026-10-17）

## 対象と調べ方

- 配備中の `ace-controller-ace-controller-deployment-0`（namespace `app`）。pod 内の `local_rag.py`・`tokkio_rag.py`・`tokkio_llm.py` は作業ツリーと差分なし。`config.yaml` は pod から読んだ（`llm_processor: NvidiaLLMRAGRouterService`、`provider: local`、route_keywords 58 語）。
- LLM は vLLM 0.9.2 の `ace-vllm-llama31-swallow-8b`（Llama-3.1-Swallow-8B-Instruct-v0.5、`--max-model-len 16384`）。
- 実例は 2026-10-17 23:19〜23:21 JST の会話ログ（controller と vLLM）。
- 事実確認は RAG コーパス（`data/rag/corpus/`、配備中の `local_rag.sqlite`）と東京工科大学の公式ページ。researchmap・東京大学側のページ・Wikipedia は見ていない。
- 修正・再配備はしていない。

## 問題（優先度順）

### 1. 追質問が RAG に回らず、LLM が根拠なしで答える（高）

- 実例: 「そうね、オープンキャンパスのあの。」は RAG で答えた。続く「いつやるか教えてほしいです。」は `outside_supported_domains` で LLM へ直行し、参考情報なしで「次回の開催日程は未定です。」と答えた。
- 原因 1: 追質問の判定 `_looks_like_followup`（`infra/rag/local_rag.py:2063-2087`）が、「それはいつ」「もっと詳しく」など限られた言い方しか拾わない。拾えないと `resolve_conversation_query` は今の発話だけを返す（`local_rag.py:2110`）。
- 原因 2: 参考情報ブロックはその1回の LLM リクエストにしか入らない（`infra/tokkio/tokkio_rag.py:428-452` は context のコピーを書き換える）。次のターンの履歴に残るのはボットの短い返答だけなので、追質問を取りこぼすと根拠がまったく無くなる。
- 再現（直前がオープンキャンパスの RAG ターン）:

| 発話 | 前の話題を引き継ぐか |
|---|---|
| それはいつですか。 | 引き継ぐ |
| もっと詳しく教えて。 | 引き継ぐ |
| いつですか。 | 引き継がない |
| いつやるか教えてほしいです。 | 引き継がない |
| 場所はどこですか。 | 引き継がない |
| 参加方法を教えてください。 | 引き継がない |

- 逆向きの懸念（コードを読んだだけで、実行はしていない）: 遡る範囲に上限がない（`local_rag.py:2112`）。長い雑談のあとに「それはいつですか」と聞くと、ずっと前の RAG の話題を引き継ぐ。

### 2. Swallow には temperature も max_tokens も送られていない（高）

- `nvidia_model_input_params`（`infra/tokkio/tokkio_llm.py:205`）が値を返すのは Nemotron 系だけで、Swallow には `{}` を返す。そのため pipecat はサンプリングの値を何も送らない。
- vLLM は起動ログのとおり、モデル同梱の generation config `{'temperature': 0.6, 'top_p': 0.9}` を使う。max_tokens は指定されず、文脈長の残りが上限になる。
- 実測: vLLM の `/metrics`（port 8011）では、起動後の 14 リクエストすべてが `request_params_max_tokens` の `le=+Inf` の区間に入っている。合計 216294 なので、1 件あたり平均約 15450 で、16384 から入力長を引いた値になる。入力は平均約 930 トークン、出力は平均約 20 トークン。
- ルーターの `temperature=0.2`・`max_tokens=64` は、`provider: nvidia` の `_stream_rag_response`（`tokkio_rag.py:522-542`）でしか使われない。`provider: local` では効いていない。
- 影響: 事実を答える場面でも 0.6 でサンプリングするので、同じ質問でも答えが揺れ、作り話も出やすい。長さの制御はプロンプトの指示だけに頼っている。

### 3. 名前・年齢の定型応答が、他人についての質問にも反応する（中）

- `_is_name_question` / `_is_kagawa_age_question`（`tokkio_llm.py:248` / `:284`）は、「名前」「何歳」と「あなた」「香川」が同じ文にあれば反応する。
- 配備中のコードで確認した結果:
  - 「あなたのお父さんは何歳ですか。」→「私は1952年9月19日生まれで、現在74歳です。」
  - 「あなたの会社の名前は」→「私は香川豊です。」
  - 「香川先生の名前の由来は」→「私は香川豊です。」
- 年齢は今日の日付から計算しており、生年月日 1952-09-19（`tokkio_llm.py:65`）は公式プロフィールと一致する。問題は判定の条件だけ。

### 4. 参考情報ブロックの作りが 8B モデルに負担をかける（中）

- 各資料の見出しに `chunk_id=…, effective_year=2026, temporal_status=current_2026, event_status=ended` という生のラベルが並ぶ（`_hit_header`、`local_rag.py:2475`）。system prompt も「temporal_statusが過年度…を示す場合」とラベル名で指示している（`infra/tokkio/customize_tokkio_japanese.py:322`）。8B モデルに内部ラベルを解釈させる作りになっている。
- 終了済みの行事でも、冒頭に「回答方針: 現在有効な参考情報に答えがある場合は内容を直接答え…」が出る（`local_rag.py:2515`）。同じブロックの本文には「開催予定である」と「【終了済み】」が両方入っている。
- 範囲外の話題で付ける `OUTSIDE_CORPUS_PROMPT_NOTE`（`local_rag.py:1843`）は「参考情報:」で始まり、「一般的な知識として簡潔に答え」と指示する。一方、system prompt は「参考情報に答えがない場合は推測で補わず、確認できないと明示」と指示している（`customize_tokkio_japanese.py:323`）。どちらに従うかがモデル任せになる。LLM の出力は実測していない。

### 5. RAG 索引が古い（中）

- 索引の作成日は 2026-07-29。コーパス `00_hachioji_open_campus_current.md` は 8/1・8/2・8/16・8/23 を「開催予定」と書いている。
- 公式ページ（https://jyuken.teu.ac.jp/jyuken/visit_oc.html）は 2026 年の来場型を 8/31 まで載せ、すべて申込終了。10/17 以降の回は載っていない。今日の「終了しました」「次回は未定」は結果として正しかったが、2 つ目は根拠なしで生成されたもの（問題 1）。

### 6. 固定プロフィールに抜けがある（低）

公式プロフィールで確認できたが、system prompt（`customize_tokkio_japanese.py:309-313`）に書かれていない項目:

- 学長就任 2023 年、副学長 2019 年、東京工科大学着任 2017 年
- 東京大学名誉教授（2017〜）、東大生産技術研究所 研究顧問（2023〜）
- 東大での経歴: 生産技術研究所 助教授（1989）・教授（1998）、工学系研究科 教授（2003）、先端科学技術研究センター 教授（2005）
- 学歴: 早稲田大学理工学部卒（1976）、同大学院 修士（1978）、博士（1984、工学博士）
- 東京生まれ、1952-09-19 生まれ（今は年齢の定型応答にしかない）

現行の記載は、学長・片柳研究所 教授・セラミックス複合材料センター長・専門分野・研究テーマのいずれも公式ページまたは KAKEN と一致した。「片柳研究所長」は 2017 年の経歴にしか出てこないので、そう書かないこと。任期の満了日は確認できていない。

### 7. 人物像と話し方の指定がない（低、判断が必要）

- 冒頭が「対話型バーチャルアシスタントです」で、話し方の指示は「標準語で自然かつ簡潔に」だけ。歓迎文「ご用件をどうぞ」、待機文「必要でしたら、いつでもお声がけください」も受付係の口調になっている。
- 参照音声（下記）の本人は「〜んですよ」「〜と思ってます」「ね」を多く使う。今の応答「私は東京工科大学の学長を務めています。」は、それより硬い。

### 8. 効いていない設定（低）

- `TOKKIO_RAG_SUFFIX_PROMPT`（`infra/tokkio/.env`）と `NvidiaRAGService.max_tokens: 64` は、`provider: local` では読まれない（`tokkio_rag.py:523`・`:542` は nvidia 経路だけ）。読む人が、効いていると誤解する。

## 参照音声の話し方

| ファイル | 長さ | 中身 |
|---|---|---|
| `/data/ACE/irodori/reference/kagawa_voice_ref_48k_mono.wav`（今の TTS 参照） | 33 秒 | AI 香川豊に向けた用意済みのメッセージ |
| `/data/ACE/irodori/reference/kagawa_ref_48k_mono.wav` | 30 秒 | インタビューでの受け答え（話題は「おふくろの味」） |

文字起こし（kotoba-whisper v2.0 と Whisper medium をつき合わせた。〔 〕は聞き取りが不確かな箇所）:

- 用意済みのメッセージ: こんにちは、東京工科大学学長の香川豊です。ついに私の分身、AI香川豊が誕生するとのこと、〔AIユニバーシティ〕としては当然の流れだと思います。これで少しは〔激務〕から解放されるでしょう。10月の全学教職員会は、私は欠席し、AIに任せようと目論んでいます。いずれにしても完成度を高めて、どこに出しても恥ずかしくないものにしてくださいね。楽しみに待っています。
- インタビュー: もう忘れちゃったけど、ないかもしれないですね。ていうかね、あのー、よくわからないんだけど、うちの親はね、なんか割合と、昔、弁当、お弁当に、割合と西洋風のいろんなのが入ってたことは思い出すんですよ。だから、これといった特定のものはないんですけども、ちょっと割合とモダンな弁当だったことは確かだと思ってます。そんなもんだね。（このあと 28 秒付近に別の人の声らしい発話がある）

話し方のクセ:

- 「割合と」（比較的、の意味）が口癖。インタビューの 24 秒で 3 回出る。
- 言い切らずに「〜と思ってます」「〜と思います」「〜かもしれないですね」で締める。
- 「〜んですよ」「〜んですけども」で、説明しながら語りかける。
- 「ね」を文の途中にも挟む（「ていうかね」「うちの親はね」「なんかね」）。改まった場面でも「〜してくださいね」と柔らかく頼む。
- 改まった場面でも軽いユーモアを入れる（「欠席し、AIに任せようと目論んでいます」）。

数値: 話速はインタビューで約 7.3 字/秒、メッセージで約 6.2 字/秒。句の間の休止は 0.3〜0.7 秒。

限界: 音声は合計で約 1 分しかない。Whisper 系はフィラーを落としやすいので、「あのー」「なんか」は実際にはもっと多い可能性がある。メッセージは原稿を読んだものらしく、普段の会話のクセはインタビューのほうに出ている。

## 推奨する修正（未実施）

1. 追質問の判定を広げる。疑問詞だけの短い発話（いつ・どこ・何時・場所・参加方法・申し込み）で、直前のターンが RAG だった場合は話題を引き継ぐ。遡りは直前 1〜2 ターンに限る。ログの組（「そうね、オープンキャンパスのあの。」→「いつやるか教えてほしいです。」）をテストに入れる。
2. Swallow 用のサンプリング値をコードで明示する（例: temperature 0.2〜0.3、top_p 0.9、max_tokens 160 前後）。値は実会話で試してから決める。
3. 名前・年齢の定型応答は、「あなたの＋名詞」（お父さん・会社・犬・由来など）のときは反応しないようにする。
4. 参考情報ブロックの生ラベルを「2026年度・終了済み」のような日本語に置き換え、回答方針の文は行事の状態に合わせて切り替える。範囲外ノートの見出しを「参考情報」以外にし、system prompt と指示をそろえる。
5. RAG コーパスを公式サイトから取り直して索引を作り直す（再配備が必要）。
6. 固定プロフィールに、問題 6 の項目を足す。
7. 話し方の指定を足すかどうかを決める。足すなら、例えば次のように「ときどき」と弱めに書く。8B モデルは口癖を毎回入れてしまいやすい。
   「です・ます調を基本にし、ときどき『〜んですよ』『〜と思っています』『〜ですね』で柔らかく締めてください。断定しすぎず、軽いユーモアは構いません。」
